## 关键决策与偏差

1. **xai 测试走 StreamSimple**：pi 的 `xaiProvider().stream(model, ctx, {reasoningEffort})` 直传 typed options；pig 的 `Provider.Stream` 只收 `*StreamOptions`，typed 字段（ReasoningEffort）经 dispatch 丢失——需要 effort 的用例走 `StreamSimple.Reasoning`（clamp 后等价），纯参数用例仍走 `Stream`。文件头声明。
2. **xai provider 测试落 `ai/providers` 包**：pi 的测试同文件 import api 与 providers；pig `ai/api` 不能 import `ai/providers`（成环），而 xai 测试必须过 provider 装配（URL/auth header），故放 providers 包。
3. **azure clone 深拷贝 compat/TLM**：pi spread 是引用共享 + copy-on-write merge，克隆点之后原模型的 merge 不影响克隆；Go 复刻该语义 = 克隆点深拷贝（否则 `mergeOpenAIResponsesCompat` 的原地写会穿透）。
4. **B2 转换层测试四个独立文件**（按 pi 一一对应命名，用户明确要求不合写）：`azure_openai_responses_reasoning_replay_test.go` / `openai_responses_foreign_toolcall_id_test.go` / `openai_responses_empty_tool_result_test.go` / `openai_responses_message_id_test.go`；catalog 落地后直接 `ai.MODELS` 取模型（gpt-4o-mini），codex 模型 id/api 手工构造（C 批前 catalog 无 openai-codex）。
5. **reasoning-replay e2e / cache-affinity e2e**：key 门控 skip，与 pi 一致；DeepSeek 端点无 encrypted_content，加密重放路径纯 mock（PLAN §0.2）。
6. **Azure URL 形态**：`{normalized-base}/responses?api-version=<v>`，normalize 后 base 已含 `/openai/v1`；非 azure host 仅去尾斜杠。无测试钉 URL（pi 的 azure 测试也只测转换层），实现按 SDK 约定。
