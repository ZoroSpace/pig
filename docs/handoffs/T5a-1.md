## 三、风险与坑（本批实证）

1. **core↔theme 依赖环**：theme.go import core（SourceInfo）。任何 core 侧新代码需要 Theme 时一律走 `core.UITheme` 结构性接口 + 调用点传 `theme.Current()`；不要试图让 core import theme（成环）。
2. **chroma `TokenType.Category()` 顶层返回自身**（`t/1000*1000`）：`for t != chroma.None; t = t.Category()` 死循环（本批踩过，已修为 `category == t` break + SubCategory 中间层）。LiteralNumber 子类只有走 SubCategory（3200）才能命中。
3. **chroma token 值带尾随 `\n`**：span 必须按行拆开闭合，否则行尾 reset 序列被 split 切到下一行，pi 的逐字节断言（如 diff 行 `\x1b[38;2;204;102;102m-old\x1b[39m`）会挂。
4. **theme.HighlightCode 不得二次着色**：高亮输出已带 theme 色，只 split("\n")；仅无语言 fallback 才逐行套 mdCodeBlock（pi 同）。
5. **tool render 状态并发**：ToolRenderContext.state 任意 goroutine 可达（renderCall 与异步 preview），组件需自带 mutex；edit 的异步 preview（computeEditsDiff.then → context.invalidate）→ goroutine + 完成后调 Invalidate，注意 -race。
6. **DiffWords 移植要点**：token 含相邻空白拼接（word+其空白）；equals 用 trim 相等；join 剥离非首 token 的前导空白；postProcess 的 dedupeWhitespaceInChangeObjects 五个分支逐字（源文件路径见上）。
7. **图片半区不可达**：`tui.GetCapabilities().Images` 恒 nil（Phase 8 检测 stub），tool-execution 的 Image 组件分支按 pi 结构留占位声明（caps.images false 时不可达），Kitty 转码（convertToPng）同样延后。
8. **in-flight 窗口类测试的 flaky**：model_catalog_refresh_test 全量 -race 下偶发 "refresh calls = 2"——第二个 caller 未进入入口时第一个已完成并拆注册。修法：放行前 sleep 10ms（本批已修）。T5a-2 的异步 preview 测试若用同类共享状态，注意同款时序。
9. **components 测试需要主题资产**：TestMain 设 `PI_PACKAGE_DIR` 指向 `../theme/testdata`（builtin 主题 sync.Once 缓存，env 必须在首次加载前置位）；新测试文件放 components/theme 包时沿用各自 testmain_test.go 的 `initTestTheme(t)`。
