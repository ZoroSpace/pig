### 0.1 token 消耗归因（按占比，用户要求复盘；对策已落 §3.5 执行纪律）

1. **「写→编译错→修」循环，~30%+**：cache-warmer 测试两次死锁（fake 锁与 w.mu 锁序反转）+ 一次 panic，每次全量 goroutine dump 诊断；`SimpleStreamOptions` 嵌入字段（CacheRetention/Env/SessionID/Reasoning）不进 struct 字面量的坑连续踩 5 次；树导航测试 7 轮收敛（BindExtensions API → loader.extensions 注入 → keepRecentTokens 缺 → 消息序列 → 嵌套设置键 branchSummary.skipPrompt → nil defaultEditor → 目标选成当前叶 → seam 撑不起 post-nav UI）。根因：边写边试，没在动笔前读齐全部 API 签与 harness 能力。
2. **编辑机制选错，~20%**：对 8k 行的 interactive_mode.go 用了十几个 python heredoc 大段精确替换，至少 3 次因 tab/空白不匹配失败即全量重付；应合并为单次 edit/write 且老文本取最小片段。
3. **大输出事故，~10-15%**：grok-mermaid 排查时 diff -r tarball 灌入 50KB minified JS（后才发现 src/ 目录）；验证 AGENTS.md 时整条 15KB 进度行原样打印两遍；多份未过滤 goroutine dump。
4. **批次过大（结构性）**：一半新功能族一半 diff-heavy 同步，按新规则应为两批；3a 推来的 5 项余量再叠一层。
5. **重复探索，~10%**：3a handoff 已给出文件清单仍对 pig 现状做了两遍不同模式的 grep 确认；pi diff 读一遍写 pig 时又回头读第二遍；thinking 里计划重建偏多，应跟 handoff 清单线性走。

## 4. 风险与坑（本批实证，下一批必读）

- **测试桩里任何被 loader/ticker goroutine 调用的回调都要原子化**（countRenderTUI 竞态教训）；新 seam 优先复用 `cacheWarmAfterFunc`（时钟）、`clipboardRunCommandFn`（进程）、`test_session_seam_test.go`（interactive 模式构造）三先例。
- **fakeWarmRuntime 锁序**：refresh 持 w.mu 时会经 getModeStopReason→getMode 回调进 fake 的锁——fake 的锁内绝不能再调 warmer 的方法（两次死锁都是这个模式）。
- `ToolDefinition.ConstrainedSampling` 是 `any`：pi fixture 不设 → 声明省键；pig fixture 设了值就会序列化，对照 pi 测试时先核对 fixture 字段。
- `types.SimpleStreamOptions` 的嵌入字段（CacheRetention 在 StreamOptions、Env 在 ProviderRequestOptions、SessionID 在 StreamOptions）**不能出现在 struct 字面量**，逐个赋值。
- interactive 测试要绕 dialog 时用 `branchSummary.skipPrompt`（嵌套键，不是扁平 branchSummarySkipPrompt）；fixture session 要可 compact 需 `compaction.keepRecentTokens:1` + u/a/u/a 四条消息。
- `session.Messages()` round-trip 必须走 `types.DecodeMessageList`（开放 union 不能直接 Unmarshal）。
- pi 测试非 ASCII 字面量先 hexdump（S6-2 教训，本批 golden 无踩）。
