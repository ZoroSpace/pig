## 1. 逐 commit 消化与 pig 落点

### 1387af7b4 项目 mcp.json 可覆盖全局服务器的开关（#10277，主半区核心）

pi 机制（`extensions/mcp/config.ts` +61）：
- 项目条目**不含 `command`/`url`/`type`** 即 override 条目（`isOverride`），仅允许 `enabled`/`exposure`/`toolExposure` 三键（`OVERRIDE_KEYS`）；多键或全局无同名服务器均报 config error。
- override 合并语义：`validateMcpServerConfig(name, {...base.config, ...value})`——以全局条目为底、项目键覆盖，`McpServerEntry.override` 记录项目文件路径；`LoadedMcpConfig` 新增 `projectConfig`（仅 trusted 时读项目文件才有值）。
- 落盘：`updateMcpServerConfig(path, name, patch, {override})`——目标文件从「定义者」变为「`entry.override ?? entry.source`」；override 条目缺省即创建 `{}` 再打补丁；`keepDefaults = isOverride(server)` 时 enabled=false 也显式写键、enabled=true 不删键（override 的显式值要保留）。/mcp 面板 `setEnabled(server, enabled, inProject)` 可把全局服务器的启停写进**项目**文件。

pig 落点（`integrations/mcp/`，pig 无 extensions 层）：
- `config.go`：later-wins 合并链中给项目级文件加 override 分支——项目条目无 `command`/`url`/`type`（pig 的 ServerConfig 对应字段）时走 override 校验：全局 manager 里须有同名、仅允许 `disabled` 键（pig 无 exposure/toolExposure 面，裁剪声明）、合成条目记 `SourcePath`=项目文件。pig 的 `ServerConfig.Disabled` 已是 M2 的 pig-only 键，override 语义天然对齐「覆盖全局 disabled」。
- `disable.go`（MCP-2 的 JSON 手术）：`SetServerDisabled` 落盘目标扩展——当胜者配置来自项目文件或本次为项目 override 时写项目 `.pig/mcp.json`（generic map 手术形态照旧）；写全局文件时对 override 条目的 keepDefaults 语义对齐 pi（disabled=false 删键仅对非 override 条目）。
- trust 门控：override 只在项目已信任时读（pig 既有 trust-requiring 探测已覆盖 `.pig/mcp.json`，MCP-1 落点核实）。
- /mcp 面板（`components/mcp_panel.go`）：启停键对全局服务器改为落项目 override（`AgentSession.MCPManager()` 需暴露项目文件路径——`core/mcp_integration.go` 装配处补 getter）。
- pi 测试 `mcp-extension.test.ts` +36 行 override 用例甄别移植到 mcp 包测试。

### 11449730c MCP 工具调用在服务器连接前可渲染（#10285，机制不迁）
