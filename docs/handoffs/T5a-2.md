**本批新增偏差与决策**（每条一句，详见各文件头）：

1. **keybinding_hints/visual_truncate/diff 移入 core/tools**：handoff 原判"core/tools → theme 无环"错误——theme→core（SourceInfo/SettingsManager）且 core→core/tools（AgentSession 注册表），core/tools import theme 即成环；连同 components→core/tools（tool-execution 的 builtin fallback）与 edit→diff 的对向边，Go 侧必须单向化。选择：theme→core 切断（决策 2）+ 三个渲染助手文件下沉 core/tools，components 改 import tools。文件位置偏差已在文件头声明。
2. **theme→core 切断**：SourceInfo 类型下沉 `codingagent/utils`（core 别名保持 API 不变）；theme_controller 的 SettingsManager 改三方法结构化接口（*core.SettingsManager 隐式满足）；theme_controller_test.go 转 theme_test 外部测试包（内部测试包会经 core→tools→theme 成环）。
3. **UITheme/ToolRenderContext/ToolRenderResultOptions 上移 core/tools、core 别名**：ToolDefinition 渲染成员签名需要这些类型，core/tools 不能 import core；core 已 import tools，方向安全。
4. **ToolDefinition.NewRenderState（pig 添加）**：pi 的 ToolExecutionComponent 用 `{}` 对象做共享 renderer state，Go 需具体值；内置定义返回 state 结构体（bash/edit），无此字段的定义由 tool-execution 兜底 `map[string]any{}`（pi `{}` 的最近类比）。
5. **ToolExecutionComponent/BashExecutionComponent 加 mutex**：updateDisplay（agent goroutine 可达）与 Render 并发，pi 单线程假设在 Go 侧显式化。
6. **elapsed ticker**：pi renderResult 的 setInterval(1s) → time.Ticker goroutine 调 context.Invalidate()，存于 BashRenderState.Interval，非 partial/error 时 Stop。
7. **图片半区 Phase 8 占位**：pendingImageComponent（渲染空）+ convertedImages 结构保留；getCapabilities().Images 恒假，分支不可达，Kitty 转码延后。
8. **Go regexp 两个坑（实证）**：① `\s` 在本仓 Go 版本任何位置都报 invalid escape（含类外）——统一写 `[[:space:]]` / 显式类；② `[+-[:space:]]` 会被误析（`+-[` 成 range）——用 `([+-]|[[:space:]])` 交替。js \s 的 U+0020 显式列入 jsSpaceClass（漏掉会让 tokenize 不携带空格，golden 全挂）。
9. **jsdiff overlapCount 越界语义**：k 超出 KMP 表时 JS 返回 undefined → maximumOverlap 取整个 string2；Go 侧 `k >= endB` 时提前返回 endB（可达条件恰为 endB==len(b)，等价）。
10. **Str/stringArg 语义**：missing key ≡ undefined ≡ ""（非 invalid）；显式 null ≡ ""；非字符串非 null 才是 invalid（write 的 content invalid 分支依赖此区分）。

## 三、风险与坑（本批实证，下一批大概率会撞）

1. **components/tool_execution.go 是并发面**：updateDisplay 全程持 c.mu，Render 也持——T5b 在 agent 事件 goroutine 里调 UpdateArgs/UpdateResult/MarkExecutionStarted 是安全的，但不要在持锁状态再调 RequestRender 以外的 ui 方法（死锁风险自查）。
2. **renderer state 类型断言 panic 即 fallback**：renderCall/renderResult 内任何 panic 被 safeCall 吞掉降级为 "toolName" 纯文本——调试渲染不显示时先怀疑 State 类型不对（必须经 definition.NewRenderState 建的类型，或 map）。
3. **Go regexp**：`\s` 全仓禁用（见决策 8）；`[+-[:space:]]` 这类混写会静默错析，写正则前先跑 30 秒小验证。
4. **theme 测试资产**：任何需要 theme 的新测试包都要 TestMain 置 `PI_PACKAGE_DIR` → `../theme/testdata`（相对包目录），且必须在首次 theme 加载前置位；core/tools 的 TestMain 在 diff_test.go。
5. **theme_controller_test.go 现为 package theme_test**：同目录新测试文件若引用非导出 theme 标识符，放 package theme 的其他文件里，别把 controller 测试改回内部包。
6. **in-flight 窗口 flaky**：bash 初始空 update 断言用了有界轮询（本批 TestToolExecutionBashInitialEmptyPartialUpdate）；T5b 若测流式 UI 时序沿用同款，不要 sleep 定值。
