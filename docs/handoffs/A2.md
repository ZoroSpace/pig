## 3. 风险与坑（给 B1）

1. **Anthropic SSE 双行格式** B1 不适用——responses 端点也是 `event:`+`data:` 双行（语义化事件），**没有 `data: [DONE]`**，终止靠 terminal event；A1 的 `iterateSseMessages`/`decodeSseLine` 可直接复用（同包）。
2. responses 的 reasoning replay：`encrypted_content` DeepSeek 不支持（mock 验证）；明文 reasoning 归并相邻 assistant——注意 values/指针双形态（plan 风险 2）。
3. `convertResponsesMessages` 的图片路由只允许 user/developer + 工具输出——system/assistant 带图 → 400，DeepSeek 会真 400（可冒烟）。
4. A1 建立的模式照抄：捕获请求用 Fetch 注入（APIKey 记得设，否则 auth assert 先挂）；payload capture 用不可达 baseUrl。
5. `//go:build smoke` 文件里的 key 只从 env 读。
