## 关键决策与偏差

1. **body 序列化共享**：SDK 的 `generateContentParametersToVertex` 与 `...ToMldev` 对 pi 用到的字段面（contents/systemInstruction/tools/toolConfig/temperature/maxOutputTokens/thinkingConfig）产出完全一致（差异只在 pi 未用的字段），抽出 `marshalGoogleGenerateContentBody` 供两个 adapter 复用——这是对「pi 两文件各自内联」的显式结构偏离（同包内、有注释声明），避免第三份逐字节重复。
2. **SDK 构造归一后置到传输时**：pi 的 SDK 在构造器里归一（project+location 互斥清除、location global 缺省、auth 充分性校验），pig 的 `googleVertexClient` 是构造配置的镜像（测试断言对象），归一与校验在 `buildVertexRequestURL`/`addAuthHeaders` 传输时执行——URL 组合 8 形态用 node 探针对 @google/genai 1.52.0 实证后 pin 进单测（express regional/global/multi-region/custom-base×4/缺省版本 v1beta1）。
3. **ADC 为 pig 原生实现**（pi 委托 google-auth-library）：三分链 + 双凭证类型 + metadata fallback + token 缓存均为新写，无 pi 行级对应物；scope 恒 `cloud-platform`。风险登记在 verify-matrix google-vertex 行（真凭证链未实测）。
4. **SDK 遥测头不复制**：SDK 默认带 `x-goog-api-client: google-genai-sdk/1.52.0 gl-node/...`，pig 不伪造（端点不要求；C3 的 mldev 传输同样未带，行为一致）。SDK 内层 pRetry 5 次重试亦不复制（pi 层 retryGoogleRequest 已提供同策略），沿用 C3 声明。
5. **C3 推迟的 vertex case 全部收口**：raw-stop-reason 三例、thinking-level-map 两例、thinking-disable 两例（env 门控 skip），三个测试文件的「随 C4 推迟」注释已清。
6. **pi 的 `process.env.GOOGLE_CLOUD_API_KEY` 占位符用例**：env 变量属 provider 认证层，adapter 从不读它——pig 用 `t.Setenv` 复现设置但走无 apiKey 选项，行为一致（ADC client）。

## 风险与坑（供后续批次）

- **models.dev 拉取需代理**：沙箱 outbound 443 黑洞，`export https_proxy=http://127.0.0.1:7890` 后 generatemodels 正常（本次两个 Google 块零漂移，14/14 与 22/22 全对上）。
- **node 探针 ADC 路会挂**：google-auth-library 的 token 刷新不走 `globalThis.fetch`（gaxios 自带传输），mock fetch 抓不到；让探针 ADC 凭证带未过期 `access_token` + `expiry_date` 可跳过网络。SDK 内层 pRetry 5 次退避会拖长探针，务必 `config.abortSignal` + 外层 `timeout`。
- **promoted 字段不能进 struct 字面量**（老坑仍有效）：测试里 `StreamOptions{APIKey: ...}` 编译失败（APIKey 在嵌入的 ProviderRequestOptions），须构造后赋值。
- **JS `split('/', 2)` ≠ Go `SplitN(s, "/", 2)`**：vertex tModel 的 publishers 映射须 SplitN 3 取前两段（丢弃第三段起），否则多段 id 产出不同路径。
