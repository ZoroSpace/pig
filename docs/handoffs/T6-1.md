**本批新增偏差与决策**（详见各文件头）：

1. **pi 可选参 → 显式参数/字段**：SettingsCallbacks 的 onThemePreview? → nil-able 字段；LoginDialogComponent 构造的 providerNameOverride/titleOverride 用 "" 表示 unset；AuthSelectorProvider.Status 用 *auth.AuthCheck（nil = unconfigured）；Method 用 any（承载 auth.ApiKeyAuth 或 auth.OAuthAuth，配 AuthSelectorMethodName 类型开关提取 name——pi 的 `method?: ApiKeyAuth | OAuthAuth` 联合在 Go 无原生形态）。
2. **pi `done(selectedValue?)` 双语义**：pig SettingsList 的 done 用 "" 表示 undefined（settings_list.go 既有约定，ThemeSubmenu/WarningSettingsSubmenu/stepped 的 cancel 均经此收敛）。
3. **AbortController → context.Context**：LoginDialogComponent.AbortController → loginAbortController{ctx,cancel}，对外暴露 Context()；pi 的 showPrompt/showManualInput Promise → 缓冲 channel + mutex 单发送守卫（OnSubmit 与 cancel 竞态下只投递一次），阻塞等待在 waitPending。
4. **pig 并发面新增 Mutator 注入**：pi 在单事件循环上改容器；pig 的 login 流跑在独立 goroutine，LoginDialogComponent 增加 Mutator 字段（接线为 InteractiveMode.mutateUI），全部 Show* 容器变更经其串行化，阻塞等待在 mutate 之外（防输入分发死锁）。
5. **异步调用面 → goroutine**：pi 的 `void this.startProviderLogin(...)` / fork onSelect 等不阻塞的 async 调用点映射为 `go func()`；同步回调（settings/trust 变更、logout 后的状态刷新）保持同步。
6. **configureHttpDispatcher 延后声明**：pig HTTP 层无全局 dispatcher 概念（Node undici 专属），onHTTPIdleTimeoutMsChange 只落 settings + status，注释声明。
7. **completeProviderAuthentication 的 deferreds**：anthropic-subscription 订阅警告（maybeWarnAboutAnthropicSubscriptionAuth）与 daxnuts 彩蛋（checkDaxnutsEasterEgg）仍按 interactive_mode.go 文件头声明延后，调用点留注释；model-catalog refresh 按 pig 同步 Refresh + goroutine 包装（pi 的 .then/.finally 链）。
8. **测试适配**：getLoginProviderOptions 投影测试无法用 pi 的 fakeThis 隔离（pig CreateModelRuntime 恒装 builtin providers），改为 RegisterNativeProvider 注入 fake provider 后按 ID 定位断言（文件头声明）；OAuthSelectorComponent render 用例留在 components 包，投影用例放 interactive 包（components 不能反向 import interactive）。
9. **冒烟实证（非 bug）**：编辑器 autocomplete 打开时 Enter 是接受补全而非提交——脚本化按键与下拉抢键会导致命令参数拼接，真人不受影响；冒烟需在抓屏确认面板状态后再发键。

## 三、风险与坑

1. **pi `done("")` 不更新**：SettingsList 的 done 回调以空串表示"不更新"，ThemeSubmenu 的 cancel 依赖此语义——T6-2 若有新 submenu 复用此模式，勿把合法空串 value 传进 done。
2. **login-dialog 的 channel 单发送**：OnSubmit 与 cancel 都会 resolvePending，新改动必须保持 mutex 守卫（双重投递会永久阻塞登录 goroutine）。
3. **Mutator 必须注入**：interactive 侧构造 LoginDialogComponent 后必须设 `dialog.Mutator = m.mutateUI`，否则 Show* 的容器变更与渲染管线竞争（TUI goroutine 之外的变更都要走 mutateUI，T5b-3 决策）。
4. **autocomplete 抢键**（本批冒烟实证）：脚本化端到端测试时 Enter 会先被 autocomplete 补全消费；人工验收正常，自动化冒烟需抓屏确认状态后再发键（坑 9 同源）。
5. **tree-selector 体量**：1427 行 + 4 套测试，若 T6-2 超 8k 行预算，把 tree-selector 单拆为 T6-2b 并更新 handoff。
