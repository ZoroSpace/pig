### 1.1 db6cc71dc — /reload 激活 defaultTools 新增工具（#10245）

**pi 语义**（`agent-session.ts` ±21 + `sdk.ts` +1 + 测试 +80）：

- `reload()` 在 `settingsManager.reload()` **前**快照 `previousDefaultTools`（仅 `usesDefaultTools` 时：`getDefaultTools() ?? DEFAULT_TOOL_NAMES`，否则空集），reload 后算 `addedDefaultTools` = 新解析结果中不在 previous 集的名字，`_buildRuntime({ activeToolNames: [...getActiveToolNames(), ...addedDefaultTools], includeAllExtensionTools: true })`。效果：新增者激活；移除不停用；会话内手动关的不复活（除非是新加入）；CLI 覆盖项因 usesDefaultTools=false 全程不参与。

### 1.2 fddc968b9 — native provider 注册时标记 provisionally configured（#10190/#9962）

**pi 语义**（`model-runtime.ts` +53/−20）：`registerNativeProvider()` 此前不更新 auth snapshot——初始模型选择在异步 refresh 落盘前读 snapshot，看到 provider 未配置 → 回落别的 provider 或误报无可用模型。修法：把 `registerProvider()` 内联的 provisional 配置块抽成 `markProvisionallyConfigured(providerId, configuredStatus, type)`，两个注册路径共用；native 路径传 `configuredRequestAuthStatus(config.getProvider(id), undefined)`、type = `oauth && !apiKey ? "oauth" : "api_key"`。注释要点：仅当 `storedProviders.has(id)` 或 configuredStatus.configured 才标记；auth map「不覆盖真实检查结果」（`if (!auth.get(id))`）；`available = all.filter(configuredProviders.has)`。

**pig 落点**（`codingagent/core/model_runtime.go`）：
- `RegisterProvider`（1432-1525）**已内联同款逻辑**（1487-1520：`stored := r.snapshot.storedProviders[providerID]` → `configuredStatus := ConfiguredRequestAuthStatus(...)` → 配置集/auth 临时表/available 重算）。抽成方法 `markProvisionallyConfigured(providerID string, configuredStatus *auth.AuthCheck, authType auth.AuthType)`，`RegisterProvider` 改调用。
- `RegisterNativeProvider`（1412-1428）在 `r.updateModelSnapshot()` 之后、`r.Refresh(...)` 之前插入调用：`r.markProvisionallyConfigured(provider.ID(), ConfiguredRequestAuthStatus(r.configProvider(provider.ID()), nil), oauthOrAPIKey)`（oauthOrAPIKey = `provider.Auth().OAuth != nil && provider.Auth().APIKey == nil` → AuthTypeOAuth 否则 APIKey；对照 pi `provider.auth.oauth && !provider.auth.apiKey`）。
- **锁结构注意**：pig 现块是分段加锁（1487-1491 读、1494-1497 写、1509-1519 写）——抽方法时保持原锁序（可整体一次 `r.mu.Lock()` 简化，与 pi 的不可变 snapshot 重建语义等价，但注意 `available` 重算读的 `all` 必须与 configuredProviders 同一 snapshot 一致性）。
- **pig 并发偏差沿用**：pig 的 Register 两路径尾部 `Refresh` 是**同步**的（1422-1424 已声明偏差），#9962 的「异步窗口」在 pig 大幅缩小；provisional 标记仍移植——语义缺口（updateModelSnapshot 与 Refresh 之间、以及 Refresh 内部可用性检查对 OAuth 的延迟）真实存在，且 pi 测试断言的是注册后**立即可查**。
- `model_registry.go:223` 的门面转发无需改。

**测试**（pi `model-runtime-modify-models-compat.test.ts` +44）：新 case「marks a native provider with a stored credential as configured when it registers」——pig 落 `codingagent/core/model_runtime_modify_models_compat_test.go`（harness 现成：`CreateModelRuntime(ctx, &CreateModelRuntimeOptions{Credentials: NewInMemoryAuthStorage(authStorageData{...}), ModelsStore: &InMemoryCodingAgentModelsStore{}, ModelsPath: lo.ToPtr(""), AllowModelNetwork: false})`，见同文件 28-75 行 `TestModelRuntimeRegistersNativeProvidersWithTheirAuthImplementation`；OAuth credential 形状参考同文件 `credData`/`authStorageData` 用法）。断言：
