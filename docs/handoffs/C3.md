## 关键决策与偏差

1. **@google/genai SDK → 原生传输**（本批最大结构工作）：SDK 面只用了 `client.models.generateContentStream(params)` + 构造参数（baseUrl/apiVersion/headers/apiKey），按 dist/node/index.mjs 源码逐条核对线格式（URL 拼接、tModel、mldev 字段提升、SSE、错误形态）。pi 测试全部 mock SDK 层、从不断言原始线格式 → pig 的 seam（`googleGenerateContentStream` 包级 var，返回 `googleChunkSource` 接口）等价 `vi.mock`。
2. **顺带修复两个 wire 缺陷（冒烟实证）**：① URL 双重 `models/` 前缀（tGoogleModel 已加前缀，buildRequest 又拼一次）；② googlePart 的 FunctionCall/FunctionResponse/InlineData 指针无 omitempty 序列化出 `"FunctionCall":null`——Google API 对 part 字段敏感，已修 + 冒烟复验。
3. **vertex 相关 case 随 C4 推迟**（在两份测试文件头显式声明）：raw-stop-reason 的 SAFETY/MAX_TOKENS/STOP vertex 三例、thinking-level-map 的 captureVertexPayload 两例、thinking-disable 的 vertex describe。google-vertex-api-key-resolution.test.ts（242 行）整体随 C4。
4. **pi fake timers（retry 测试）→ 真实 500ms 退避**：RetryProviderRequest 的退避一次性 ≤500ms，直接等待，无 flake。
5. **onPayload 捕获用 panic**：pig 的 OnPayload 无 error 返回（C1 定式），测试回调 panic("payload captured") → adapter recover → errorMessage 语义与 pi 的 throw 等价。
6. **convertTools 返回值改 (value, error)**：pig 的 ResolveJSONSchemaStrictSampling/GetJSONSchemaToolParameters 返回 error（pi throw），ConvertGoogleTools 顺延。

## 风险与坑（本批实证，C4 大概率撞）

- **gofmt 对齐毁文本锚点**：多轮 sed/python 替换时，锚点在 gofmt 后对齐会变（`ContentIndex: blockIndex(),` 的空格数）；替换脚本要用稳定语义锚点或整段替换，别信手抄的旧文本。

- **promoted 字段不能进 struct 字面量**（C1 老坑仍有效）：StreamOptions.APIKey/Headers 构造后赋值。
