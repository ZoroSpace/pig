## 1. 交付明细（按 commit）

### 1.1 Anthropic workload identity federation（a9424cd43，#10242/#10177）

**核心判断**：pi 把交换完全委托给 `@anthropic-ai/sdk@0.124.0` 的 `config: {authentication: {type: "oidc_federation"}}`；pig 的 anthropic adapter 是手写 HTTP 不走 SDK，故本项不是「同步」而是把 **SDK 的 federation 半区原生复刻进 Go**。pi 仓库无 node_modules，从 npm 拉取 0.124.0 源码（`lib/credentials/{oidc-federation,token-cache,identity-token,types}.mjs`、`core/credentials.mjs`）逐文件核对 wire 形状后落 `ai/api/anthropic_federation.go`（新文件，~430 行）。

**wire 契约（与 SDK 逐项对齐）**：
- 交换：`POST {baseURL}/v1/oauth/token`，JSON body `{grant_type: "urn:ietf:params:oauth:grant-type:jwt-bearer", assertion, federation_rule_id, organization_id, service_account_id?, workspace_id?}`；headers `Content-Type: application/json` + `anthropic-beta: oauth-2025-04-20,oidc-federation-2026-04-01` + UA `anthropic-sdk-typescript/0.124.0 oidcFederationProvider`（pig 保持 SDK 的 UA，因 pig 在此扮演的就是 SDK）。
- 断言上限 16 KiB（超限客户端侧报错，`Math.ceil` KiB 文案对齐）；identity token 文件**每次交换现读**（支持 K8s projected token 轮换）+ trim + 空文件报错。
- `requireSecureTokenEndpoint`：https 强制，http 仅放行 localhost/127.0.0.1/::1。
- 响应解析（pi `parseTokenResponse`）：`access_token` 必需、`token_type`（若给）必须 bearer（大小写不敏感）、`expires_in` 必须有限（JS `Number.isFinite`；Go 侧 `encoding/json` 对缺失字段给零值 0，与 JS NaN 同判「missing required fields」，行为一致）、错误体经 `redactSensitive`（RFC 6749 §5.2 SAFE_ERROR_KEYS 白名单 + 2000 字符截断）、非 2xx 报文带 request-id 与 401 的 workspace-id 提示文案（逐字对齐）。
- **token 缓存**（pi `TokenCache` 两级刷新全语义）：进程级 `anthropicFederationTokenCache` 单条目（= pi 的 `federationClient` 包级变量，键 `JSON.stringify([baseURL, config])`；Go 函数不可比较，fetch 身份用 `reflect.ValueOf().Pointer()` 比对），剩余 >120s 用缓存、30–120s 回陈旧 + 后台刷新（失败保陈旧 + 5s 退避）、<30s 阻塞刷新；阻塞刷新经 `refreshing` channel 合并并发（= pi pendingRefresh 去重）。
- messages 请求：`Authorization: Bearer <token>` + `anthropic-beta` **追加**（非覆盖）`oauth-2025-04-20`（= SDK `prepareRequest`；pig 在 betas 参数落 header 之后追加）。

**pi 侧接线**：env 常量 5 个落 `ai/env_api_keys.go`（不进 `getApiKeyEnvVars`——它们不是 API key，与 pi 一致）；provider resolve 末位回落 `ai/providers/anthropic.go`（三个必需 env 缺一即 `nil`，两个可选原样透传，返回 `{Auth:{}, Env:federation, Source:"workload identity federation"}`，键/token 优先级不变）；adapter 侧 `getAnthropicFederation(model, apiKey, headers, env)` 守卫（仅 `provider=="anthropic"` 且无 request auth），`stream`/`streamSimple` 两入口替换 `assertRequestAuth`（拆出 `hasAnthropicRequestAuth` 复用），`createAnthropicClient` 增 federation 分支（apiKey/authToken 双空 = pi 的 `apiKey: null, authToken: null`）。

### 1.2 Anthropic copy code 登录（7a11fe1c7，#10194）

`ai/auth/oauth_anthropic.go`：`anthropicCopyCodeRedirectURI = "https://platform.claude.com/oauth/code/callback"`；`Login` 先发 `select` prompt（"Select Anthropic login method:"，browser 默认/copy_code headless，选项文案逐字对齐），`copy_code` 走新增 `loginAnthropicCopyCode`（auth URL 换 redirect_uri，auth_url 提示与 manual_code 文案逐字对齐，占位符 `code#state`，state 不匹配/缺 code 报错文案同 pi，交换时 redirect_uri 用 copy-code 值）。pig 的 `AuthInteraction` 本就支持 `select`/`manual_code`，`interactive_mode.showAuthPrompt` 的 `showAuthSelect` 分支现成，**UI 层零改动**。

### 1.3 strict 翻转修复（295cc72b0，#9953）

`ai/api/constrained_sampling.go`：新增 `UnsupportedStrictSchemaKeywordCheck`（`func(key, value) bool`），穿透 `makeJSONSchemaNodeStrict`（在 UNSUPPORTED_STRICT_SCHEMA_KEYS 之后逐 entry 检查，报错文案 `key: <json> is unsupported`）→ `MakeStrictJSONSchema` → `ResolveJSONSchemaStrictSampling`；`GetJSONSchemaToolParameters` 保持 nil check（pi `getJsonSchemaToolParameters` 同样不传——strict=true 蕴含 check 已通过）。六个调用点中仅 anthropic 传 `isAnthropicStrictUnsupportedKeyword`（两张 keyword/format 表落在 `anthropic_messages_convert.go`；minItems 仅 0/1 放行；format 限 10 种字符串格式），其余 5 家（google/bedrock/responses/completions）显式传 nil。测试：pi 把「只给 strict 工具发全量 input_schema」从 eager-compat 测试文件迁到新 `anthropic-strict-tool-schema.test.ts` 并加 #9953 回归——pig 同构迁移（`TestAnthropicEagerToolInputStrictSchemas` 移出 eager 文件成 `anthropic_strict_tool_schema_test.go` 两函数），**stash 验证红→绿**（call site 改 nil 即红）。

### 1.4 grammar tool calls 回放丢 mismatched item id（bc2d8dc1c，radius#115）

`ai/api/openai_responses_shared.go`：id 前缀判据从「fc_ 或否」改为按回放形态取期望前缀（function_call→`fc_`、custom_tool_call→`ctc_`），`isDifferentModel` 或前缀不匹配一律丢弃 id（foreign id 先被归一化成 fc_*，再回放成 custom_tool_call 时前缀必不匹配 → 丢弃，消掉 OpenAI 配对校验 400）。测试：`ai/api/constrained_sampling_test.go` 新建（pi constrained-sampling.test.ts 的 radius#115 用例；该文件更早的 makeStrictJsonSchema/appendGrammarToolInputJsonDelta 用例是 S11 前的既有缺口，本批不扩scope，见 §4）。

### 1.5 Retry-After 不可解析 → 指数退避（2bbfcca43，#9571）

`ai/utils/provider_retry.go`：`retry-after-ms` 解析值非有限（Go `ParseFloat` 接受 NaN/Infinity，与 JS `Number.isFinite` 判据对齐）→ 落到 `retry-after`；`retry-after` 数值解析失败且非 HTTP 日期（= JS `Date.parse` NaN）→ 落到指数退避（旧行为是 validate(NaN) 睡 0）。pi 未加测试；pig 补 `TestGetRetryDelayMSUnparseableRetryAfterFallsBackToExponential`（375–500ms 指数窗口三例）。

### 1.6 Z.AI CN 端点 overflow（3dd803d7e，#10208）

`ai/utils/overflow.go` 追加 pattern `prompt exceeds max length`（紧跟 prompt too long 之后，pi 同位）+ `overflow_test.go` 回归（code 1261 CN 文案）。

## 3. 偏差与跳过声明

1. **SDK 401-invalidate-and-retry-once 未移植**（`TokenCache.invalidate` + `shouldRetry` 首段）：pi 以 `maxRetries: 0` 调 SDK，该路径在 pi 的实际用法下是死代码；pig 的两级刷新 + 过期阻塞刷新已覆盖缓存正确性。
2. **SDK 的 profile/config 文件凭证链未移植**（`~/.config/anthropic/configs/<profile>.json`、`ANTHROPIC_CONFIG_DIR`）：pi 从 env 合成 config 走的是「无 config 文件」分支；文件形态属 SDK 内部面，pig 只复刻 env 合成路。dogfooding 撞到再立项。
3. `expires_in` 缺失时 Go 零值 0 即判缺失（pi JS 为 NaN），错误文案同；**有意的**语义并轨而非偏差。
4. `docs/providers.md` 的 2 行 federation 文档不迁（pig 无该文档镜像）。
5. copy code 登录的真机 TTY 冒烟归 S11 收尾批统一做（计划稿 §3 收尾段冒烟清单本就含 copy code 登录；pig 无 Anthropic 订阅凭证时无法走完真机浏览器段，与 verify-matrix 现有 anthropic OAuth 行同批次解锁）。
6. pi 的 federation sdk 测试（anthropic-federation-sdk.test.ts）在 pig 落为 fake-fetch 线级断言（pig 无 SDK 可 mock，同 anthropic-auth-token 测试的既有转换手法）。
