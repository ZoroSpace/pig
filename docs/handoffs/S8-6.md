## 2. 偏差与决策(均已落代码注释)

1. **faux.ts +2 不移植**:pi 的 faux provider 是测试专用 provider,pig 的测试用自有 mock harness(fauxHarness/bareModel),无 faux 对应物;inputLimits 字段随 harness 模型直构覆盖。
2. **cache-retention.test.ts ±2 与 fireworks-models.test.ts +1 不补**:两文件 pig 历来未移植(存量缺口,非本批引入);其行为断言(strict 翻转后的 runtime 默认)由新 `strict_tools_test.go` 两用例等效覆盖;cerebras_strict_test.go 的期望翻转(false→omitted)已按 8bfef4de8 同步。
3. **ProviderModelConfig 仅穿 InputLimits**:pig 扩展注册面是声明过的 slim 子集(无 input/thinkingLevelMap/promptCache),Phase 7 已取消,不扩面;pi 的 +2 字段单独穿通(字段+tag+RegisterProvider 转换)。
4. **image_process.go 是对 09-22 fix 批的 pi 对齐修正,非纯增量**:MaxEncodedBytes(raw 字节口径)→MaxBytes(base64 payload 口径,与 catalog 字段注释「Maximum base64-encoded payload size」及 Anthropic 5MB 限一致);补默认 4.5MB 预算与 early-return 体积检查(pi DEFAULT_OPTIONS + inputBase64Size 条件);JpegQuality 字段兑现(原 pig 恒 q80 硬编码)。既有「单次 q55 重试、不做 PNG/JPEG 双编码、不做渐进缩维」等 09-22 已声明偏差维持不变。既有测试期望无破坏(预算不可达用例 base64 口径下同样不可达)。
5. **可选整数字段用 plain int64**(非指针):schema min 1 ⇒ 0=unset,零值安全,与 Model.ContextWindow/MaxTokens 先例一致;合并函数以零值检查复刻 TS spread。
6. **pig-only seam 三件**:core.processImageFn / core.normalizeToolResultImagesFn(pi vi.mock 替换模块函数的等价物)+ utils.ResizeImageFn(pi image-resize 模块 mock 等价物;`ResizedImage` 随之导出,pi 本就导出)。
7. **eaf72 的 concurrent roles 期望**:pig 在 S8-4 收口时已按 v0.87.0 语义对齐(当时即需 "system"),本批无需改动,仅记录。
8. **catalog 上游漂移随重生成带入**:claude-opus-5-5 族(bedrock 6 profile+anthropic+openrouter)、gpt-6-luna/sol 族(openai/azure/opencode/vercel/openrouter)、grok-4.7、mimo-v2.6 族、cohere/command-a-plus、qwen3.8-omni-flash 等入;`*:batch` 若干出;residential golden 同步重 sync(S7/C2 先例:golden 重同步为显式决策)。
