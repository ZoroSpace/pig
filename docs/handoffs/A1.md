**本批新偏差与决策**：

1. **client 注入 → Fetch 注入**：pi 的 `AnthropicOptions.client`（预构建 SDK 实例）无 Go 对应物；pig 用 StreamOptions.Fetch 覆盖同一注入面（文件头注释声明）。
2. **OnPayload 无法 throw**：pi 的 payload-capture 测试在 onPayload 里 throw 阻断请求；pig 的 OnPayload 返回值无 error——测试改为捕获后让请求打向 127.0.0.1:9 失败。
3. **`betas` → `anthropic-beta` header**：SDK 行为由 createMessage 复现（params["betas"] → header，逗号连接）；测试直接断言 header 或 body.betas。
4. **anthropic-version: 2023-06-01**：SDK 默认头，pig 显式补齐（真 Anthropic 端点必需）。
5. **修复 pig 既有潜伏 bug（constrained_sampling.go）**：`MakeStrictJSONSchema` 的 required 数组顺序此前随 map 迭代随机——偏离 pi 的 Object.keys 文档序，且打碎 strict 工具的 prompt-cache 前缀稳定性。修复：json.Decoder token 走一遍记录每个对象的键序（collectJSONKeyOrders），strict 变换按文档序产出。A1 eager-compat 测试锁定。
6. **anthropic SDK 重试面不搬**（plan 已声明）：RetryProviderRequest 走既有 helper。
7. 每次事件 push 前快照 content/partial（plan 风险第 2 条落实，与 openai_completions_stream 同模式）。

## 3. 风险与坑（给 B1）

- **本工具链（~/.g/go go1.25.0）拒绝 `f(x, y...)` 混合变参调用**（`append(s, 1, t...)` 同样报 "too many arguments"）——非标准 Go 行为，先 append 再展开绕开。
- ai/api 的测试 import ai/providers 会成环（providers→api）；catalog 读取用 `ai.MODELS`。
- catalog 无 claude-fable-5-1（v0.85.1 新模型，B2 catalog 再生成时补）；mid-convo 测试用 inline 构造模型。
- message_start 事件是 `{type, message:{...}}` 嵌套，remarshal 要取 `event["message"]`。
- SSE 帧间必须空行（\n\n），fake transport 少一个 \n 会把多个事件拼进一个 data。
