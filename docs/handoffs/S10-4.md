### 1.7 cwd 语义对齐修复（双向兼容实验抓出的存量 bug）
- **根因**：pi main.ts 的 `cwd = process.cwd()`——bun/node 返回内核 getcwd(3)（symlink 已解析，macOS `/tmp/x` → `/private/tmp/x`）；pig main.go 的 `os.Getwd()` 优先采信 `$PWD`（保留 symlink 拼写）。会话目录名由 cwd 编码 → 同一目录下两侧会话目录名不同（实测 `--tmp-s10-final--` vs `--private-tmp-s10-final--`），`--continue`/`/resume` 互不可见，trust 键、git 命令参照同样分裂。
- **修复**：新 `codingagent/cli/process_cwd.go` `ProcessCwd()`——`os.Getwd()` 后 `filepath.EvalSymlinks`（失败回落原值，对齐 canonicalizePath 语义）；**windows 保持原值**（其 getcwd 等价物不解析 junction，pi/bun 同形态，声明偏差）。`cmd/pig/main.go` 单点接线（会话 cwd 的唯一源头）。`cli/file_processor.go`/`cli/startup_ui.go` 的独立 `os.Getwd` 不改（仅作文件访问参照，两拼写指向同一 inode，无会话目录编码参与）。
- **回归**：`codingagent/cli/process_cwd_test.go`（无 symlink 场景不漂移 + symlink 场景解析到真实路径）。

## 2. 批内发现并修复的问题
1. **cwd symlink 语义偏差（§1.7）**：`os.Getwd()` vs `process.cwd()` 的语言层差异经双向兼容实测暴露（pi `--continue` 找不到 pig 会话、反之亦然）——`ProcessCwd()` 修复 + 回归锁定。**长期影响**：所有此前在 symlink 目录（/tmp、macOS /var）下创建的 pig 会话与 pi 会话目录名从此统一；存量 pig 会话目录名不变（无迁移，`--continue` 找旧目录的旧行为本就与 pi 不一致）。
2. 测试基建：`stubClipboardReaders` 补 file-paths seam 隔离——真实 `ReadClipboardFilePaths` 在 darwin 上会 shell out 到 osascript 读环境剪贴板，交互包测试从此不再受本机剪贴板状态污染。
3. 复盘（非本批引入）：`agent_session_disposition_test.go` 初版断言写成了常量 vs 常量的同义反复，stash 验证立刻暴露——**回归测试断言必须锁字面量或双向独立推导**。
