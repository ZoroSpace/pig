## 0. 批次外收获（最重要的部分）

本批用 pi v0.86.1 生成器（独立 worktree，node v24 直跑 TS）产出完整 `data/*.json`，与 pig dumpcatalog 做**首次全 catalog 逐字段对照**（此前 golden 只覆盖 google/google-vertex/bedrock 三家）。结果：625 → 5 个差异（剩 4 个为两次抓取间 OpenRouter 上游漂移 + 1 个已声明 pig 偏差），过程中确认并修复 **7 个存量源码缺口**（全部先于本批存在）：

1. **三个 merge 函数漏 `SupportsMidConvo*` 分支**（metadata.go；S6-1 漏——S6-1 加了 struct 字段但 mergeOverrideNonNil/mergeOpenAIResponsesCompat/mergeAnthropicOverrideNonNil 的手写字段枚举没跟上）。影响：openai/openai-codex/opencode/opencode-go/github-copilot 全部 GPT-5.4+ 模型与 anthropic opus 系的 `supportsMidConvoSystemMessages` 在 catalog 中丢失 → 运行时把可中途插 system 消息的模型当作折叠语义处理。**用户可见 bug**。
2. **openrouter 的 `anthropic/*` 模型未路由 anthropic-messages**（fetch.go；Phase 2 openai-completions 时代缺口，anthropic-messages adapter 落地后从未回补）：补 `^anthropic/`（非 `:batch`）→ anthropic-messages @ `https://openrouter.ai/api` + 新建 `openrouter_reasoning_options.go`（getOpenRouterThinkingLevelMap 整文件）。
3. **潜伏正则 bug**：`` regexp.MustCompile(`^~?anthropic\\/`) `` 在 Go raw string 里是「反斜杠+斜杠」字面量，永远匹配不上（metadata.go supportsAnthropicMidConvoEffort 的前缀剥离从没生效过）；同型修正 fetch.go 新写的路由正则为 `^anthropic/`。
4. fireworks 规则 `glm-5p2` → `glm-`（pi v0.86.0 起就是宽匹配，glm-5p3 全族走错 anthropic 分支）。
5. baseten GLM-5.2 text-only input override（pi: supportsImageInput = !isGlm52 && …）缺失。
6. `applyAnthropicMessagesCompatMetadata` 漏 `mergeThinkingLevelMap(model, {off: null})`（supportsMidConvoEffort 模型）+ `applyAnthropicAllowedFallbackModelMetadata` 漏 supportsMidConvoEffort 兼容性过滤。
7. **extension_selector.go 的 Description 渲染缺失**（T6-1 加了 Options 字段但构造器没接线，pi v0.86.0 起 description 渲染在 title 之下）——/bug 各选择器的说明文本此前整段不显示。
